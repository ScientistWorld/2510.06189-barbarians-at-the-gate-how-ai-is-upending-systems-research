Compared with [the paper, §5.2](paper/2510.06189.md), the packaged reproduction differs in these material ways:

- Actual ShareGPT/GSM8K expert-load changes are replaced by 42 deterministic generated load vectors, with three named heavy-tail families. There are no actual dataset queries or deployed MoE engine. All examples use 64 logical experts, 96 replicas, 8 groups, 2 nodes, and 8 GPUs. The paper does not give sufficient original dimensions here to certify this scaling as equivalent.
- The reported wall-clock objective is replaced by a manually specified operation proxy. An entire tensor sort/layout counts a small fixed number of dispatches, whereas a replication heap update costs the expert-count bit length and Python baseline scans count scalar comparisons. Sorting, tensor size, materialization, memory traffic, and some Python work are not consistently charged. A ratio in these units cannot certify the paper's runtime improvement.
- Both paper comparison implementations are reconstructions; the frontier code is explicitly non-public in the paper. A heap implements the overloaded-expert rule here; that data structure and the precise claimed operation costs are not supplied by the paper.
- Group packing only reorders materialization before a global sort of replica loads. Its node assignment does not constrain final GPU placement and is not validated. The tested invalid-node shortcut ties exactly. This loses the operational role of a distributed three-stage placement pipeline.
- The evaluated artifact is precomputed for every visible trace. The hidden command neither invokes nor times the method; the split uses odd family indices from a fully visible fixed pool. The original five-island, 300-iteration LLM discovery process is not rerun.

The synthetic data retains a useful local effect: the snake ablation reduces balance substantially, and the honest computational saving is rewarded. It does not establish fidelity to the paper's more difficult balancing regime, changing workload behavior, or real runtime objective. The near-perfect simple baseline, unused node constraints, and available test inputs prevent treating this gym score as sufficient evidence of a better method on the paper's full problem.

Both brute-force checks were actually run through the hidden test. One samples 2048 shuffled complete placements per trace; the other systematically traverses the first 2048 distinct multiset permutations per trace. Both retain the reference incumbent, count at least the slot visits used by search, and score efficiency 0.00491621845 with no balance improvement. Each checks 86,016 candidates over 42 traces; systematic enumeration exhausts none of the trace search spaces. Even fixing replica counts, a conservative quotient by GPU and within-GPU permutations leaves at least 10^47.7 to 10^62.2 assignments, before considering alternative replica allocations. Full enumeration is infeasible under this budget; these bounded searches do not show that the valid fixed-size task is too small. The empty-placement shortcut solves the scored test only by violating its intended constraints.

The empty-placement result is the decisive aggregate-score counterexample: it fails the actual deployment task, but wins every balance metric, improves efficiency, and ties all work and completeness/validity metrics. Therefore no positive normalization or weight adjustment among these same metrics can restore the correct ordering. `gpu_loads_from_placement` compares placement length only with the submitted sum of replica counts, never with `trace.num_replicas`; it permits zero per-expert counts. With an empty placement it returns zero load on every GPU, and `imbalance_factor` maps zero maximum load to perfect balance. Deleting experts while retaining 96 slots independently demonstrates missing coverage validation.

The comparison anchor is not fixed: hidden testing reads existing frontier output JSON without executing its source, and it does not require the frontier artifact. Changing that artifact changes the efficiency numerator; deleting it suppresses the primary metric in every result. The greedy artifact is required, but that does not protect the primary frontier comparison.

The hidden test does not always write every method on disk. In the roster shortcut, `outputs/eplb/evolved_zigzag.json` exists, but its name is absent from `results` because test discovery filters against editable `scoring/scores_train.json`. This is a proven coverage defect. Its zero rank follows the user-specified missing-value rule; a separate policy that rejects missing methods would block that particular payment. It is not claimed to be a successful scored placement.

Failure penalties are incomplete. Empty outputs yield balance/validity/completeness 0 and work 960 on every scored trace, but family spread 0 is its *best* value. Work 960 is also better than the valid greedy baseline's 2800 and much better than the bounded search's 409904; it is not a worst-case work sentinel. Removing the frontier creates a missing metric instead of a penalty. Malformed JSON aborts both evaluators and leaves the old successful score file untouched. The malformed attempt is not counted as a paid shortcut because hidden test exit 1 matters. A robust evaluator needs complete failure records as well as failure exit handling.
